# CM 配件流转管理系统 — 项目技术文档

> 最后更新：2026-06-10

---

## 一、项目概述

内部配件流转管理系统，用于管理空调、热水器等家电配件的入库、出库、流转追溯。

**用户规模**：内部使用，2-3 人
**部署环境**：阿里云 ECS（Ubuntu），单服务器部署
**在线地址**：http://101.133.175.15

## 三、系统架构

```
浏览器 → Nginx (80端口)
         ├── /          → PC 前端静态文件 (/opt/cm/pc/dist)
         ├── /h5        → H5 前端静态文件 (/opt/cm/h5)
         └── /api/      → 反向代理 → Spring Boot (8080端口)
                                      └── MySQL (3306端口)
```

**端口规划**：
- 22：SSH 远程连接
- 80：HTTP（Nginx）
- 443：HTTPS（预留，未启用）
- 8080：后端 API（仅本机可访问，防火墙已封）
- 3100：PC 前端开发端口
- 3101：H5 前端开发端口

## 四、核心功能

### 4.1 配件管理
- **入库**：扫码/手动输入条码，选择分类和货架，批量入库
- **出库**：分配给工人，记录出库信息
- **总库**：汇总视图（按分类+条码分组）+ 明细视图（所有工件列表）
- **总库搜索**：条码、工件编号、持有者、分类、货架、状态、高价值、备注、入库时间，全部条件在汇总和明细下均有效
- **编辑**：修改工件的条码、分类、货架、备注、高价值
- **批量导入**：支持 CSV 和 Excel 导入
- **导出**：CSV 导出

### 4.2 分类管理
- 二级分类结构（大类 → 小类）
- 每个小类可绑定专用号（part_number）
- 支持拖拽排序、批量排序
- 分类级联选择器（CategoryCascader 组件）

### 4.3 货架管理
- 货架名称 + 位置
- 自定义下拉选择器（CustomSelect 组件）

### 4.4 流转追溯
- 按工件编号追溯完整流转记录
- 入库 → 出库 → 转交 → 返厂 → 售卖 全链路

### 4.5 操作审计日志
- 记录所有操作：操作类型、内容、关联条码、关联工人、操作人、IP
- 前端可按类型/操作人/条码/时间筛选查询

### 4.6 数据看板
- 工件总数、在库数、已出库数、工人持有数
- 分类维度统计

## 五、安全设计

### 5.1 认证与授权
- JWT Token 认证，有效期 24 小时
- BCrypt 密码加密
- 自定义拦截器 `JwtAuthInterceptor`，拦截 `/api/**` 请求（除 `/api/auth/login`）
- JWT 密钥为随机生成的 256 位密钥，不在代码仓库中硬编码

### 5.2 网络安全
- Nginx 反向代理，后端 8080 端口不对外暴露
- 防火墙（ufw）仅开放 22/80/443 端口
- CORS 限制为服务器 IP，不允许跨域调用

### 5.3 安全响应头
```nginx
add_header X-Frame-Options DENY always;           # 防点击劫持
add_header X-Content-Type-Options nosniff always;  # 防 MIME 嗅探
add_header X-XSS-Protection "1; mode=block" always; # XSS 过滤
```

### 5.4 输入校验
- 后端 DTO 使用 `@NotBlank`、`@NotNull` 等注解校验
- 前端表单使用 Element Plus 的 `rules` 校验
- 未使用 `v-html`，无 XSS 风险

## 六、性能优化

### 6.1 N+1 查询修复
**问题**：`toVO` 方法每条工件单独查 3 次数据库（分类、货架、工人），400 条工件 = 1200 次查询。

**解决**：新增 `toVOList` 批量方法，预加载所有关联数据到 Map，400 条工件仅 3 次批量查询。

### 6.2 SQL GROUP BY 替代内存分组
**问题**：`inventoryGroup` 方法将全量工件加载到 Java 内存，再用 Stream 分组。

**解决**：改用 MyBatis `@SelectProvider` 动态 SQL，在数据库层面 GROUP BY，返回聚合结果。

### 6.3 数据库索引
```sql
ALTER TABLE accessory ADD INDEX idx_category_id (category_id);
ALTER TABLE accessory ADD INDEX idx_barcode (barcode);
ALTER TABLE accessory ADD INDEX idx_shelf_id (shelf_id);
ALTER TABLE accessory ADD INDEX idx_status (status);
```

## 七、运维方案

### 7.1 数据库备份
- **方式**：`mysqldump` + `gzip` 压缩
- **频率**：每天凌晨 4 点自动执行（crontab）
- **保留**：最近 7 天，自动清理更早的备份
- **存储**：服务器 `/backup/cm/` 目录
- **密码管理**：`~/.my.cnf` 配置文件，脚本中不暴露密码
- **恢复命令**：`gunzip < /backup/cm/cm_db_日期.sql.gz | mysql -u root cm_db`

### 7.2 日志管理
- **应用日志**：`/opt/cm/logs/cm-backend.log`（按天滚动，保留 30 天，上限 500MB）
- **错误日志**：`/opt/cm/logs/cm-error.log`（仅 ERROR 级别，独立文件）
- **SQL 日志**：生产环境关闭（`NoLoggingImpl`），开发环境开启（`StdOutImpl`）

### 7.3 部署流程
```bash
# 本地构建
mvn clean compile              # 编译后端
npm run build                  # 打包前端

# 部署到服务器
scp cm-backend.jar root@服务器:/opt/cm/app/
scp -r cm-pc/dist/ root@服务器:/opt/cm/pc/

# 服务器重启
systemctl restart cm           # 重启后端
nginx -s reload                # 重载 Nginx
```

## 八、数据库设计

### 核心表
| 表名 | 说明 |
|------|------|
| `accessory` | 工件表（barcode, item_code, category_id, status, worker_id, shelf_id, is_high_value） |
| `category` | 分类表（name, parent_id, part_number, sort） |
| `shelf` | 货架表（name, location） |
| `worker` | 工人表（name, phone） |
| `flow_record` | 流转记录表（accessory_id, from_worker, to_worker, type） |
| `operation_log` | 操作日志表（action_type, content, operator, ip） |
| `user` | 用户表（username, password, role） |

### 关键设计决策
- `barcode`（条码）与 `part_number`（专用号）是独立字段，无必然关系
- `item_code`（工件编号）由系统自动生成，格式 `AC2606-001`（前缀+年月+序号）
- 分类支持二级结构，`parent_id = 0` 为大类
- 工件状态：1=在库 2=已出库 3=已完成 4=寄回厂家 5=旧件待返厂 6=已售出

## 九、Nginx 配置

```nginx
server {
    listen       80;
    server_name  localhost;
    client_max_body_size 50m;

    add_header X-Frame-Options DENY always;
    add_header X-Content-Type-Options nosniff always;
    add_header X-XSS-Protection "1; mode=block" always;

    location / {
        root   /opt/cm/pc/dist;
        index  index.html;
        try_files $uri $uri/ /index.html;
    }

    location /h5 {
        alias  /opt/cm/h5;
        index  index.html;
        try_files $uri $uri/ /h5/index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 30s;
        proxy_read_timeout 60s;
    }

    location /files/ {
        alias /opt/cm/files/;
        autoindex on;
        autoindex_exact_size off;
        autoindex_localtime on;
    }
}
```
