# 开发规范总纲

> 配件流转管理系统 (Circulation Management System)  
> 版本：V1.0 | 更新日期：2026-05-27

---

## 1. 总则

本文档为项目开发的顶层规范，所有前后端开发工作必须遵守。子规范（后端、前端、数据库、API、UI、Git）在不与本规范冲突的前提下可做细化补充。

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| **一致性** | 同类功能保持相同的代码风格、命名方式、交互模式 |
| **简洁性** | 不过度设计，不做当前不需要的抽象 |
| **可读性** | 代码即文档，变量名/函数名自解释，关键逻辑有注释 |
| **可维护性** | 分层清晰，职责单一，修改一处不影响全局 |
| **规范性** | 遵守本文档定义的所有约定 |

## 2. 项目命名规范


## 3. 代码风格通用约定

### 3.1 命名风格

| 场景 | 风格 | 示例 |
|------|------|------|
| Java 类名 | PascalCase | `AccessoryService`, `FlowRecord` |
| Java 方法名 | camelCase | `findByBarcode`, `transferOut` |
| Java 常量 | UPPER_SNAKE_CASE | `FLOW_TYPE_INBOUND` |
| 数据库表名 | snake_case | `accessory`, `flow_record` |
| 数据库字段 | snake_case | `create_time`, `worker_id` |
| Vue 组件文件名 | PascalCase | `AccessoryForm.vue`, `FlowTimeline.vue` |
| Vue 变量/函数 | camelCase | `accessoryList`, `handleSubmit` |
| CSS 类名 | kebab-case (BEM 风格) | `.flow-card__header`, `.scan-btn--primary` |
| API 路径 | kebab-case | `/api/flow-record`, `/api/inventory-owner` |
| 环境变量 | UPPER_SNAKE_CASE | `VITE_API_BASE_URL` |

### 3.2 注释规范

- **Java**：类、接口、公开方法必须有 Javadoc 注释；核心业务逻辑行内注释。
- **Vue**：组件顶部 `<script>` 块内写组件说明注释；复杂逻辑行内注释。
- **SQL**：表和字段必须有 COMMENT。
- **注释语言**：统一使用中文，与代码中的英文标识符区分。

### 3.3 文件组织

- 单个文件不超过 **300 行**（不含模板），超过则拆分。
- 单个函数不超过 **50 行**，超过则提取子函数。
- 单个目录下文件不超过 **15 个**，超过则按功能分子目录。

## 4. 版本控制约定

- 主分支：`main`（生产环境代码）
- 开发分支：`dev`（日常开发）
- 功能分支：`feat/xxx`（从 dev 分出，完成后合回 dev）
- 修复分支：`fix/xxx`（从 main 分出，修复后合回 main 和 dev）
- 提交信息格式：`<type>(<scope>): <subject>`
  - type: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`
  - scope: `backend`, `pc`, `h5`, `db`, `docs`
  - 示例：`feat(backend): 实现配件入库接口`
  - 示例：`fix(pc): 修复扫码组件在 Safari 下不工作的问题`

---

## 5. 错误处理约定

### 5.1 后端

- 所有异常通过全局异常处理器统一捕获。
- 业务异常使用自定义 `BusinessException`，携带错误码和提示信息。
- 不向客户端暴露堆栈信息和技术细节。

### 5.2 前端

- Axios 拦截器统一处理 HTTP 错误（401/403/500）。
- 业务错误由页面组件自行展示（ElMessage 提示）。
- 表单提交前必须前端校验，不依赖后端校验。

---

## 6. 安全约定

- 密码使用 BCrypt 加密存储，禁止明文。
- 接口必须 Token 鉴权（登录接口除外）。
- SQL 查询全部使用参数化查询（MyBatis-Plus 自动处理）。
- 前端禁止使用 `v-html` 渲染用户输入内容。
- 敏感配置（数据库密码、JWT 密钥）不出现在代码中，使用配置文件。

---

## 7. 文档维护

- 每次功能变更，同步更新相关文档。
- API 文档使用 Apifox / Swagger 维护，与代码同步。
- 数据库表结构变更，同步更新 `init.sql` 和表说明文档。
