## 2. 分层职责与调用关系

```
Controller → Service → Mapper
    ↓           ↓         ↓
  参数校验    业务逻辑   数据访问
  返回响应    事务管理   SQL 执行
```

### 2.1 Controller 层规范

- 使用 `@RestController` + `@RequestMapping` 定义接口。
- 方法参数使用 `@Validated` + DTO 接收，禁止直接使用 `HttpServletRequest` 取参。
- Controller 层**不写业务逻辑**，只做参数接收、校验、调用 Service、返回 Result。
- 每个方法必须有 Swagger 注解（`@Operation`、`@Parameter`）。

```java
@RestController
@RequestMapping("/api/accessory")
@Tag(name = "配件管理")
public class AccessoryController {

    @Autowired
    private AccessoryService accessoryService;

    @PostMapping("/inbound")
    @Operation(summary = "配件入库")
    public Result<Void> inbound(@Validated @RequestBody AccessoryInboundDTO dto) {
        accessoryService.inbound(dto);
        return Result.success();
    }

    @GetMapping("/{barcode}")
    @Operation(summary = "根据条码查询配件")
    public Result<AccessoryVO> findByBarcode(@PathVariable String barcode) {
        return Result.success(accessoryService.findByBarcode(barcode));
    }
}
```

### 2.2 Service 层规范

- 接口定义在 `service/`，实现在 `service/impl/`。
- 实现类使用 `@Service` 注解。
- 涉及多表操作的方法必须加 `@Transactional`。
- 业务异常使用 `throw new BusinessException(ResultCode.XXX)` 抛出。
- Service 方法命名规范：
  - 查询：`getById`, `listByXxx`, `findByXxx`
  - 新增：`create`, `save`, `inbound`
  - 修改：`update`, `modify`
  - 删除：`delete`, `remove`
  - 业务操作：`transferOut`, `transferIn`, `sell`

### 2.3 Mapper 层规范

- 继承 `BaseMapper<Entity>`，简单查询直接使用 MP 内置方法。
- 复杂查询（多表关联、动态条件）写在 XML 映射文件中。
- 禁止在 Mapper 中写业务逻辑。

### 2.4 Entity 层规范

- 使用 `@TableName` 指定表名。
- 主键使用 `@TableId(type = IdType.AUTO)`。
- 使用 `@TableField(fill = FieldFill.INSERT)` 自动填充 `create_time` 等字段。
- 使用 Lombok `@Data` 简化 getter/setter。
- 必须有中文注释说明字段含义。

```java
@Data
@TableName("accessory")
public class Accessory {
    @TableId(type = IdType.AUTO)
    private Long id;

    /** 配件条码 */
    private String barcode;

    /** 配件名称 */
    private String name;

    /** 规格型号 */
    private String spec;

    /** 分类ID */
    private Long categoryId;

    /** 单位 */
    private String unit;

    /** 备注 */
    private String remark;

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}
```

## 3. 统一响应格式

```java
@Data
public class Result<T> {
    private int code;       // 响应码：200成功，其他为错误
    private String message; // 响应消息
    private T data;         // 响应数据

    public static <T> Result<T> success() {
        return success(null);
    }

    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.setCode(200);
        r.setMessage("操作成功");
        r.setData(data);
        return r;
    }

    public static <T> Result<T> error(int code, String message) {
        Result<T> r = new Result<>();
        r.setCode(code);
        r.setMessage(message);
        return r;
    }
}
```

### 错误码定义（ResultCode）

| 错误码 | 含义 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录 / Token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 业务冲突（如条码重复） |
| 500 | 服务器内部错误 |

## 4. 异常处理规范

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    /** 业务异常 */
    @ExceptionHandler(BusinessException.class)
    public Result<?> handleBusiness(BusinessException e) {
        return Result.error(e.getCode(), e.getMessage());
    }

    /** 参数校验异常 */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleValidation(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining("; "));
        return Result.error(400, msg);
    }

    /** 未知异常 */
    @ExceptionHandler(Exception.class)
    public Result<?> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.error(500, "系统繁忙，请稍后重试");
    }
}
```

## 5. JWT 鉴权规范

- 登录成功后签发 JWT Token，有效期 24 小时。
- Token 放在请求头 `Authorization: Bearer <token>`。
- 通过 `HandlerInterceptor` 拦截除 `/api/auth/**` 外的所有请求。
- Token 解析成功后将用户信息存入 `request.setAttribute`，供 Controller 使用。

## 6. 事务管理规范

- 涉及多表写操作的方法必须加 `@Transactional`。
- 只读查询方法加 `@Transactional(readOnly = true)`（可选优化）。
- 事务方法内抛出 `RuntimeException` 才会回滚，业务异常需指定 `rollbackFor = Exception.class`。

```java
@Transactional(rollbackFor = Exception.class)
public void transferOut(FlowTransferDTO dto) {
    // 1. 校验库存
    // 2. 扣减总库存
    // 3. 增加师傅库存
    // 4. 写入流转记录
    // 5. 写入操作日志
    // 以上步骤任一失败，全部回滚
}
```

## 7. 日志规范

- 使用 SLF4J + Logback（Spring Boot 默认）。
- Controller 层不需要打日志（由拦截器统一记录请求日志）。
- Service 层在关键业务节点打 INFO 日志。
- 异常处打 ERROR 日志，包含异常堆栈。
- 日志格式：`[类名.方法名] 消息内容`

```java
log.info("[FlowService.transferOut] 配件领用：条码={}, 师傅={}", barcode, workerName);
log.error("[FlowService.transferOut] 领用失败", e);
```

## 8. 配置管理规范

- 使用 `application.yml` + `application-{profile}.yml` 多环境配置。
- 数据库连接、JWT 密钥等敏感信息放在 `application-dev.yml`，不提交 Git。
- 提供 `application-dev.example.yml` 作为配置模板。
- 配置项必须有注释说明。
