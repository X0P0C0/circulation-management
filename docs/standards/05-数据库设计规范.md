# 数据库设计规范

> 配件流转管理系统 | MySQL 数据库  
> 版本：V1.0 | 更新日期：2026-05-27

---

## 1. 命名规范

### 1.1 数据库名

- 使用小写字母 + 下划线：`cm_db`
- 禁止使用 MySQL 保留字

### 1.2 表名

- 使用小写字母 + 下划线：`flow_record`, `inventory_owner`
- 表名使用**单数**形式：`worker` 而非 `workers`
- 模块前缀（可选，当表较多时）：本项目不加前缀，直接用语义化名称
- 关联/中间表：`inventory_owner`（清晰表达关联关系）

### 1.3 字段名

- 使用小写字母 + 下划线：`create_time`, `worker_id`, `flow_type`
- 主键统一命名为 `id`
- 外键命名为 `{关联表名}_id`：`worker_id`, `category_id`, `accessory_id`
- 布尔字段：`is_xxx` 格式（本项目用 status 整型替代）
- 时间字段：`{动作}_time` 格式：`create_time`, `update_time`
- 禁止使用驼峰命名

### 1.4 索引名

- 主键索引：`PRIMARY`
- 唯一索引：`uk_{字段名}`：`uk_barcode`
- 普通索引：`idx_{字段名}`：`idx_worker_id`, `idx_category_id`

## 2. 字段类型规范

| 场景 | 类型 | 示例 |
|------|------|------|
| 主键 | `BIGINT UNSIGNED AUTO_INCREMENT` | `id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT` |
| 外键 | `BIGINT UNSIGNED` | `worker_id BIGINT UNSIGNED` |
| 短文本（≤50字符） | `VARCHAR(50)` | `barcode`, `name`, `unit` |
| 中文本（≤255字符） | `VARCHAR(255)` | `remark`, `spec` |
| 长文本 | `TEXT` | 不超过 2 个 TEXT 字段 |
| 整数数量 | `INT UNSIGNED DEFAULT 0` | `qty`, `total_qty` |
| 状态/类型 | `TINYINT UNSIGNED` | `status`, `flow_type` |
| 时间 | `DATETIME` | `create_time DATETIME DEFAULT CURRENT_TIMESTAMP` |
| 密码哈希 | `VARCHAR(100)` | `password_hash` |

### 禁止使用的类型

- `ENUM`：使用 `TINYINT` 替代，在代码层用枚举约束
- `FLOAT/DOUBLE`：金额等精确数值使用 `DECIMAL`（本项目暂无金额场景）

## 3. 表结构模板

```sql
CREATE TABLE `表名` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `字段名`      类型            NOT NULL DEFAULT '默认值' COMMENT '字段说明',
  `create_time` DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_xxx` (`字段名`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='表说明';
```

## 4. 设计原则

### 4.1 每张表必须有

- `id` 主键（BIGINT UNSIGNED AUTO_INCREMENT）
- `create_time` 创建时间
- `update_time` 更新时间
- 每个字段必须有 `COMMENT`

### 4.2 逻辑删除 vs 物理删除

- **流转记录、操作日志**：禁止物理删除，仅通过状态标记（如需要）
- **师傅、分类**：使用逻辑删除（`status` 字段：0=禁用/已删除，1=正常）
- MyBatis-Plus `@TableLogic` 注解自动处理

### 4.3 外键约束

- **不使用数据库外键约束**，在应用层维护关联关系。
- 原因：外键约束影响写入性能，且不利于数据迁移。

### 4.4 字符集

- 数据库、表、字段统一使用 `utf8mb4` + `utf8mb4_unicode_ci`。
- 原因：支持 emoji 和全角字符。

### 4.5 存储引擎

- 统一使用 `InnoDB`，支持事务和行级锁。

## 5. 索引设计规范

- 频繁作为查询条件的字段必须建索引。
- 单表索引数量不超过 **5 个**。
- 联合索引遵循**最左前缀**原则。
- 区分度低的字段（如 status）不单独建索引，可作为联合索引的后置字段。

### 本项目索引规划

| 表 | 索引 | 字段 | 说明 |
|------|------|------|------|
| accessory | uk_barcode | barcode (UNIQUE) | 条码唯一 |
| accessory | idx_category_id | category_id | 按分类查询 |
| inventory | idx_accessory_id | accessory_id (UNIQUE) | 配件唯一库存 |
| inventory_owner | idx_worker_id | worker_id | 按师傅查询 |
| inventory_owner | uk_accessory_worker | accessory_id, worker_id (UNIQUE) | 配件+师傅唯一 |
| flow_record | idx_barcode | barcode | 按条码追溯 |
| flow_record | idx_worker_id | worker_id | 按师傅查询 |
| flow_record | idx_create_time | create_time | 按时间查询 |
| flow_record | idx_flow_type | flow_type | 按类型筛选 |
| operation_log | idx_create_time | create_time | 按时间查询 |
| operation_log | idx_action_type | action_type | 按类型筛选 |

## 6. 数据安全

- 数据库用户使用专用账号，不使用 root 连接应用。
- 配置文件中数据库密码不提交 Git（使用 `.gitignore` 排除）。
- 定期备份数据库（crontab + mysqldump）。
- 生产环境数据库禁止开启远程 root 登录。
